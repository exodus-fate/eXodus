## 2. The game in one page

*In 1997 a regional TV station shut down. Nineteen years later it transmits at
00:00 every night, and the broadcast shows events inside the building before
they happen.* Players are investigators for the **National Broadcast Recovery
Division (NBRD)**. In Case 01 they enter **Broadcast Station 04**, recover
three transmitter components, shut the broadcast down and extract.

- **The Time-Shift Deck** (core mechanic): VHS tapes found in the station show
  *future* CCTV footage on CRT decks. Some events on a tape are **editable**
  (diamond markers): change their state (e.g. "LIGHTS FAIL" → "LIGHTS HOLD")
  for a **charge** (3 per team in Standard). Each edit has an **authored
  consequence** elsewhere (circle markers; amber = linked). Edits lock 5 s
  before the event fires. Invalid edits never cost a charge.
- **The Presenter** (the entity): a tall suited figure with a CRT/static face.
  States: *Dormant, Observing, Displaced, Hunting, Rewinding* (+ internal
  *Searching*). It follows the **committed timeline** (scripted routes per
  event state), senses players (line of sight, light, flashlight, noise,
  refuges), winds up before every hunt, loses players, has a hunt time limit,
  never kills — it takes players "off-air" (spectate; one revive per player).
- **Anomalies:** *the Loop* (a corridor section repeats; spot the odd prop to
  break it) and *the Caller* (a radio voice that lies about the keypad code).
- **Objectives:** tapes → deck edits → restore generator (prime, start) →
  keypad cage (real code over radio Channel 2 with the live clock) →
  install components in the transmitter → freight-door climax → extraction
  van at the loading dock → false-safety beat → case report (grade, rewards).
- **Lobby:** the NBRD **field office** (HQ): terminals (case board, archive,
  equipment locker, store, settings), desks with nameplates, ready-up and a
  6 s deploy countdown.
- **Progression:** credits, research, clearance, evidence archive, tape
  replays with hidden frames, master recordings, challenges, cosmetics,
  loadout presets, desk decor, Restricted mode, weekly Archive Challenge
  leaderboard. **Monetisation** is cosmetic/convenience only (ids all `0`
  until created; store hidden).

The full spec is `docs/DESIGN_BRIEF.md` (sections: originality boundaries,
mechanic, fairness rules, core loop, scare design, the Presenter, map rules,
art direction, lighting values, model specs, UI specs, controls, progression,
monetisation, module responsibilities, timeline execution rules, signal,
multiplayer, saving/security, audio, accessibility, performance, acceptance
checklist).

### Data flow (the most important idea)

1. **Client sends intent only** through two remotes: `Action` (fire-and-forget)
   and `Request` (RemoteFunction returning a result table). Never outcomes.
2. **Server validates** (Router: type checks + per-player rate limits;
   services: range, phase, ownership, charges…).
3. **`MissionCore` (pure) decides** and **emits effects** (`{type=..., ...}`)
   into a queue. It never touches Instances.
4. **`MissionService` drains effects** and applies them through the other
   services (WorldService lights/doors/items, EntityService commands,
   remotes to clients…).
5. **Snapshots replicate** to clients (`Mission` remote, versioned, throttled
   to ≥0.1 s with a 1 s heartbeat). The client UI renders only from snapshots
   and cues. Rewards/unlocks/purchases are server-only.

### Boot order

Server (`Main.server.luau`): validate every case with
`TimelineCore.validateCase` (refuses to start if broken) → install any
configured texture MaterialVariants (`Surfaces.install`) → `Net.create` → `Router.init` → init
DataService, WorldService, MarketService, InteractionService, EntityService,
SignalService, TimelineService, EvidenceService, MissionService,
LobbyService → bind station + HQ prompts → idle lights.

Client (`Main.client.luau`): `Net.wait` → `State.init` → safeInit (pcall) each
controller in order: Audio, HUD, Camera, Input, Deck, Menu, Report, Spectate,
Keypad, Effects, Monitors, Tools, Prompts, Tutorial → wire callbacks
(`InputController.onTool/onDeck/onMenu`, `CameraController.onFootstep =
AudioController.footstep`) → text scaling for every `DeadAir*` ScreenGui →
request profile.

## 6. Contracts (names other code depends on)

### Remotes (`ReplicatedStorage.Remotes`)
Events: `Action` (C→S), `Mission`, `Subtitle`, `Cue`, `Notify`, `Report`, `Profile`, `Party`, `Ghosts` (S→C). Function: `Request` (C→S→C).

**Actions:** DeckClose, DeckOpen, Flashlight, InspectEvent, LeaveCase, RecordAnomaly, ReturnToHQ, SetReady, TeamVoteReply.
**Requests:** BuyCosmetic, CommitEdit, GetArchive, GetLeaderboard, GetProfile, GetStore, JoinMission, LoadPreset, MarkFrame, PromptBundle, PromptPass, Revive, SavePreset, SaveSettings, SelectCase, SetCosmetic, SetDecor, SetEquipment, SetTutorialSeen, SubmitCode, TeamRecovery.

### Cues (server → client `Cue` remote, also some local)
Alarm, BroadcastStart, CageOpen, DoorForced, DoorLocked, **DoorMoved** {door, open, kind}, EditCommitted, EditorShadow, Eliminated {userId}, Extracted, GeneratorPrime, HuntEnd {reason}, HuntStart {targetId}, Install, LightsFail, LoopBreak, LoopReset, LoopStart, OnAir, OpenDeck {deck}, OpenKeypad, OpenMenu {page}, PowerOn, PresenterAppear, PresenterVanish, ReplayBriefing, Revived, Rewind {room, duration}, TeamVote, TransmitterArmed. ## 7. Data models

### 7.1 Case definition (`Config/Cases/Case01.luau`)
Top-level keys: `id, number, title, location, summary, mapId, masterRecording, timeLimit, maxParticipants, modes, briefing, decks, tapes, tapeOrder, events, items, components, optionalEvidence, interactables, loop, keypad, radio, radioChannels, objectives, optionalObjectives, flagLabels, anchors, doorLocks, spawns, checkpoints, hiddenFrames, challenges, variants`.

  ```lua
  { id, label, tape, cameras, locationId, eventType, anchor, offset,
    isEditable, originalState, allowedStates, stateLabels, editCost, maxEdits,
    lockBefore, prerequisites, consequenceEventIds, clue, warning,
    derivedFrom = "otherEvent", stateMap = { OTHER_STATE = "MY_STATE" }, -- consequences

                         presenter = { kind = "Displaced"|..., duration, huntOnSight, sight, path = { {t, pos} } } } } }
  ```
  Fire time = anchor time (a flag like `broadcast_start`) + `offset`. Derived (consequence) events take their state from the source via `stateMap`.
- **items:** `{label, kind = "Tape"|"Component"|"Key", tape?, spawns = {P(...)}, visibleFlag?, hint?}`.
- **interactables:** `{kind = Briefing|Deck|Generator|Cage|Relay|Socket|Lever|Van|BoardRack|Evidence|Ambush|Rewind|..., room, pos, object, ...}`.
- `P(room, u, v, y)` positions everywhere (see MapLayout).

## 8. Audio pipeline

- **All 125 sounds are original**, synthesised in Python (`scripts/audio/`):
  `dsp.py` (oscillators, noise colours, envelopes, zero-phase FFT filters with a
  `circular()` mode for loops, convolution reverb, tape wow/flutter, tape stop,
  saturation), `sfx.py` (one-shots: UI, footsteps ×4 surfaces ×4 variants,
  doors, deck, keypad, machines, Presenter, Loop, stingers, sounds matching the
  case's subtitle descriptions), `loops.py` (ambience beds and machinery,
  exactly periodic), `music.py` (8 looping tracks: Menu, Lobby, Briefing,
  Explore, Tension layer, Hunt, Extract, Report — 1960s library music on worn
  tape).
- `build_banks.py` renders, levels (RMS target per category with a peak
  ceiling, DC removed), packs into **4 banks** (`DeadAir_Sfx.ogg`,
  `DeadAir_Ambience.ogg`, `DeadAir_Music1.ogg`, `DeadAir_Music2.ogg`), writes
  `Config/AudioBank.luau` + `assets/audio/banks.json`. Loops are stored as
  `[last 1 s][loop][first 1 s]` so the LoopRegion jump lands on matching audio.
  Output is byte-identical between runs.
- **In game:** each Sound plays a slice via `PlaybackRegionsEnabled` +
  `PlaybackRegion` (+ `LoopRegion`, `Looped` for loops).
- **Why banks:** Roblox caps monthly audio uploads; 4 uploads cover everything.
- **To enable:** upload the 4 `.ogg` files as the experience owner, then
  `python3 scripts/audio/upload.py --ids Sfx=… Ambience=… Music1=… Music2=…`
  (or `ROBLOX_API_KEY=… python3 scripts/audio/upload.py --user <id>` /
  `--group <id>` using Open Cloud). The upload path is written but untested
  against live Roblox; the `--ids` path is tested.
- Adding a sound: function in `sfx.py`/`loops.py`/`music.py` → entry in
  `Audio.Sounds` → `build_banks.py` → re-upload that bank. The audio spec
  fails if any name used in code is missing.

## 12. Lessons and gotchas (things that bit us)

- **FootageView must strip LayerCollectors** (SurfaceGuis) from cloned rooms — rooms contain CCTV monitors whose SurfaceGuis contain cloned rooms… this exploded to 1.3M instances once. Also strip Lights, ProximityPrompts, Sounds.
- **Roblox cylinders run along X** (diameter = min(Y,Z)); balls use the smallest side. A map test now checks round parts are sized consistently.
- **Find things by attribute/tag, not name** — the server tolerates Studio edits to the map.
- **Client never decides outcomes**; even UI states (deck availability, prompts) come from snapshots/promptState.
- **Determinism**: gameplay randomness uses `Util/Rng` (xorshift32) seeded per run, never `Random`/`math.random` (those are fine for cosmetics only). Python's `hash()` is randomised per run — don't use it in the audio generator.
- `TextLabel.Font` (enum) doesn't serialise well for baking → use `FontFace` everywhere (UI.new does this by default).
- Lune `fs` calls yield and metamethods can't yield → the harness pre-reads all files.
- GUI Frames are click-through unless `Active = true` (the tutorial backdrop needed it).
- The custom ProximityPrompt UI must redraw when the server changes `ActionText` etc.
- The deck fires a local `LocalEditCommitted` and the server echoes `EditCommitted` — dedupe effects (audio uses a 1.5 s dedupe).
- ScreenGuis with equal DisplayOrder have undefined stacking — keep orders unique where it matters.
- Luau's `string.format("%d", 70.6)` truncates (no error).
- Roblox's default "Running" footstep sound is muted client-side (replaced by surface footsteps).
- `CameraController` only adds position offset + roll after the camera scripts; adding pitch/yaw would drift because the camera module reads `CFrame.LookVector` back.
